# 브라우저 시나리오 테스트

`pytest`는 렌더된 페이지에 문자열이 **있는지**만 확인할 수 있다. 그 문자열을 사용자가 **볼 수 있는지**는 확인하지 못한다. 실제로 `sr-only` 편집 상태 바는 두 커밋 동안 모든 문자열 단언을 통과하면서 사용자에게 아무것도 보여주지 않았다(F-01).

여기 있는 것은 그 간극을 메우는 시나리오다. 카카오 SDK를 최소한으로 대역(double)하고 `fetch`를 목킹해서 **운영 편집 코드 그대로** 실행한 뒤, 실제 DOM 상태를 관찰한다.

## 검증 대상

| # | 시나리오 | 지키는 것 |
| --- | --- | --- |
| T-1 | 보정 실패 | 오류가 **보이고**, 닫기 전까지 사라지지 않고, 편집값이 유지된다 |
| T-2 | 저장 거부 (course_id 4,096자 초과) | 사유가 보이고 저장 버튼이 다시 살아난다 |
| T-3 | 보정 성공 | 거리 배지가 응답 `length_km`를 따라간다 |
| T-4 | 요청 중 연타 | 요청이 **1건**만 나가고 툴바가 잠긴다 |
| T-5 | 지우개로 만든 빈 구간 | 저장이 막히고 **그 사유가 화면에 계속 남는다** |
| T-7 | 되돌리기 | 경로와 거리가 함께 복원된다 |
| T-8 | 안내 문구 | 자동으로 사라져 지도를 오래 가리지 않는다 |

## 실행

```bash
.venv/bin/python tests/browser/build_harness.py /tmp/runart-harness
```

`harness.html`(일반 코스)과 `harness_animal.html`(동물 코스)이 생성된다. 정적 서버로 띄운 뒤 브라우저에서 열고, `edit_scenarios.js`를 콘솔에 붙여 넣고 실행한다.

```javascript
await runEditScenarios()   // → {pass, fail, results}
```

`fail`이 0이어야 한다.

## 한계

- 카카오 대역의 투영(projection)은 의도적으로 단순한 대체물이다. 이 시나리오들은 **피드백·요청 상태 머신**을 검증하며 지도 투영 정확도는 검증하지 않는다.
- 실제 제스처·pan/zoom 충돌·안전 영역은 등록 도메인과 `KAKAO_JAVASCRIPT_KEY`가 있는 실기기 검증(S3)에서만 확인된다.
- 아직 `pytest`에 연결되어 있지 않다. 러너(Playwright 등)를 도입할 때 `runEditScenarios()`의 반환값을 그대로 단언하면 된다.
