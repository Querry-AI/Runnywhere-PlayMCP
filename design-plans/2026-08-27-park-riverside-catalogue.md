## 동작 규칙

- 공원·강변·한강·하천·호수·수변·물가·물을 보면서 뛰는 추천 요청은
  `need_facilities=["park"]`로 한 번 호출한다. 다섯 곳은 하나의 공통 풀이다.
- 출발지가 없으면 묻지 않고 중복 없이 세 곳을 무작위 추출한다.
  반복 요청에서 같은 조합이 다시 나올 수 있으며 세 장소의 중복만 금지한다.
- 출발지가 있으면 등록 경로의 실제 시작점까지의 직선거리로 가까운
  세 곳을 정렬한다. 도보거리나 이동시간이 아니다. 출발지의 주소·상호를
  임의로 역 이름으로 바꾸지 않는다. 잘못된 출발지는 무작위 추천으로
  바꾸지 않고 오류로 안내한다.
- 위젯 이전 안내에서 공원으로 이동해야 함을 명시한다. 카드·지도·마무리
  문구 모두 실제 공원 이름과 실제 경로 거리·시간을 사용한다.
- 고정 코스는 요청 거리·시간에 맞게 변형하지 않는다. 추가 조건이 있으면
  고정 경로의 실제 조건과 다를 수 있음을 안내한다. 동물 요청과 함께 오면
  공원 일반 코스임을 알리고 동물 모양을 완성했다고 말하지 않는다.
- `water`는 음수대/마실 물이다. 물가 풍경 요청은 `park`이고, 음수대 요청은
  공원 추천 모드를 켜지 않는다. 기존 코스 주변 시설 문의는 기존 시설 도구를 쓴다.
- 2026-08-28 완화: 야간 요청은 조명 보통 수준인 0.33 이상을 허용한다.
  어두움 범위(0.32 이하) 및 관측 근거가 없는 기본값은 제외한 뒤 무작위/거리순
  선택한다. 세 곳 미만이면 `insufficient_courses`로 안내한다. 현재 저장 경로 다섯 곳이
  모두 통과한다. 조명 정보는 현장 안전이나 개방 상태의 보장이 아니다.

## 저장·복원과 검증

`park_course_presets.json`은 경로 노드와 파라미터를 저장한다. 모든 구간은
현재 그래프의 공원·강변 보행로에서 골랐으며, 재방문 왕복 구간도 그대로
유지한다. 다리나 직선을 만들어 연결하지 않는다. 런타임에는 경로를 새로
탐색하지 않고 기존 `course_from_path`로 실제 거리·상승고도·조명을 다시 계산한다.

체크섬과 그래프 지문을 검증하고, 출발점과 공원·강변 비율도 다시 확인한다.
기존 `manual_path` 기반 course ID를 사용하므로 서버 캐시가 없어도 같은
경로로 복원된다. 생성 스크립트는 `scripts/build_park_presets.py`이다.
도로·시설 데이터나 경로를 다시 만들면 체크섬도 갱신해야 한다.

실제 로컬 MCP 함수 호출에서 출발지 없는 요청, 강남역/홍대 기준 요청,
야간 요청 모두 세 카드와 세 지도 링크를 반환했다. 응답은 약 19~20KB로
기존 24KB 제한 이내였으며, 그래프 로드 이후 호출은 약 4~5ms였다.
이는 로컬 서버 계약 검증이며 카카오 배포 화면 확인을 뜻하지 않는다.

최종 검증: 전체 회귀 테스트 459개 통과(51.99초). 기존에 재현해 기록한
프로세스 풀 미사용 시 고래 코스 생성 시간 초과 테스트 1개만 제외했다.
다섯 장소에서 가능한 세 장소 조합 10개 모두 위젯 용량 제한을 통과한다.
